## 1. المعمارية البرمجية والهندسية الحالية (Repository Architecture)

### 1.1 حزمة التقنيات والتبعيات الفعلية (Tech Stack)
وفق ملف [`package.json`](file:///d:/novixa-work/hadramout-center-platform/package.json):
- **إطار العمل:** Next.js 16.4.1 (معمارية App Router مع React Server Components).
- **نظام إدارة المحتوى:** Payload CMS 3.92.0 (تشغيل كحزمة مدمجة في مسار `src/app/(payload)`).
- **مكتبة الواجهات:** React 19.3.1 + React-DOM 19.3.1.
- **قاعدة البيانات:** SQLite عبر محول `@payloadcms/db-sqlite` 3.92.0 وقارئ `node:sqlite` المدمج في Node.js 24.
- **محرر النصوص الغني:** `@payloadcms/richtext-lexical` 3.92.0 مع مكون مخصص مبني على Tiptap 3.32.0 (`src/admin/fields/HtmlField.tsx`).
- **معالجة الصور:** Sharp 0.35.5.
- **بيئة التشغيل المعتمدة:** Node.js `>=24.22.1`.

### 1.2 بنية المجلدات وتقسيم المسؤوليات
- `src/app/(site)/[locale]`: مسارات الواجهة العامة متعددة اللغات (Server Components افتراضياً، مع عزل مكونات العميل التفاعلية في مجلد `client`).
- `src/app/(payload)`: مسار لوحة التحكم `/admin` ونقاط نهاية واجهة برمجة التطبيقات `/api`.
- `src/collections`: تعريف مجموعات المحتوى (`content.ts`، `Pages.ts`، `Media.ts`، `Users.ts`، `Authors.ts`، `Categories.ts`، إلخ).
- `src/globals`: الإعدادات العامة للمنصة (`Site.ts`).
- `src/proxy.ts`: خادم وسيط يعالج رؤوس الأمان، حدود القراءة من الواجهة البرمجية (`limit<=100`, `depth<=2`)، إعادة التوجيه للغات، وحظر GraphQL.
- `src/lib`: طبقة منطق الأعمال والبيانات الخفيفة (استعلامات قاعدة البيانات، توليد SEO، JSON-LD، والتعامل مع اللغة العربية).
- `docs/`: الأرشيف التوثيقي التاريخي والمؤسسي، ويُضاف إليه اليوم `docs/modernization/`.

### 1.3 حالة بيئة التطوير المحلية (Local Environment Diagnostic)
- عند تشغيل فحص الأنواع (`npm run typecheck`) ظهرت أخطاء `TS2307: Cannot find module 'next'` و`@types/node`.
- **السبب الجذري المؤكد:** مجلد `node_modules` غير موجود محلياً في مساحة العمل الحالية (`Test-Path node_modules = False`).
- **قرار مرحلة A:** التزاماً بالقاعدة الإلزامية للمرحلة A (عدم تثبيت أي حزم برمجية أثناء التدقيق والتخطيط)، لم يتم تنفيذ `npm ci` محلياً. يتم توثيق هذه الخطوة كمتطلب أولي إلزامي عند بدء المرحلة B.

- معالجة ثغرات حاسمة (منع رفع SVG المهدد بـ XSS، رؤوس منع التضمين، وتقييد دور المراجع لحقول الترجمة فقط).

### 3.2 أوجه القصور الحادة في إدارة الصفحات (Pages Collection)
- بالرجوع إلى [`src/collections/Pages.ts`](file:///d:/novixa-work/hadramout-center-platform/src/collections/Pages.ts):
  - الحقول المتوفرة: `title`, `slug`, `body`, `status`, `translationMeta`.
  - الحقل النصي `body` هو مجرد `textarea` يعتمد على محرر HTML خام.
  - **الغياب التام لمنشئ الصفحات (No Page Builder):** لا يمكن للمحرر إضافة قسم تعريفي، أو شبكة بطاقات، أو معرض صور، أو قائمة روابط، أو أزرار دعوة للعمل (CTA) إلا بكتابة HTML يدوياً، وهو أمر مستحيل للمحرر غير التقني.
  - **انعدام حقول SEO:** لا يمكن للمحرر تخصيص عنوان ميتا أو وصف أو صورة مشاركة لصفحة بعينها، مما يجعل الصفحات تعتمد على عنوان الصفحة التلقائي وقصاصة من النص الخام.
  - **انعدام التحكم بموضع الصفحة في القوائم:** لا يوجد حقل لتحديد هل تظهر الصفحة في القائمة الرئيسية، أو القائمة المنسدلة، أو التذييل، أو تكون صفحة هبوط مستقلة.
  - **انعدام نظام المعاينة الحية:** لا يستطيع المحرر معاينة شكل الصفحة في التصميم الحقيقي قبل النشر، مما يؤدي إما لنشر محتوى غير جاهز أو التردد في التحرير.

## 5. خلاصة نتائج التدقيق

النظام مستقر برمجياً وقوي من حيث البنية التحتية، ولكن تكمن الفجوة الأكبر في:
1. افتقار لوحة التحكم لأدوات البناء البصري الآمن للصفحات (Page Builder).
2. افتقار المحرر للمعاينة الحية الفورية.
3. التبعية لروابط ملفات PDF على خادم خارجي قد يتوقف بعد فك ارتباط النطاق القديم.
4. الحاجة لتنظيم معمارية المعلومات واستيعاب متطلبات تقرير المركز دون تشويه الهوية البصرية الحالية.
