# قرار اختيار المنصة والإطار (Framework Decision Record)

> **التاريخ:** 14 أكتوبر 2026 · **السبب:** طلب صاحب المشروع تقييم أيّ منصة أفضل: الاستمرار على الإطار الحالي أم الانتقال لمنصة أنضج وأكثر احترافية.
> **الخلاصة:** **الانتقال إلى Next.js 16 + Payload CMS 3 (TypeScript) + SQLite**، مع الإبقاء على كل ما بُني ويصلح لأي إطار (المستورد، المعقِّم، أدوات العربية، مزوّدو الترجمة، الاختبارات).

## 1. لماذا أعدنا التقييم؟

عند بدء التنفيذ كان القرار الأول **خادماً مخصصاً** (Fastify + SQLite + قوالب مكتوبة يدوياً). بعد بناء الأجزاء الأساسية تبيّن أن الجزء الأكبر القادم هو **نظام إدارة محتوى كامل** (مصادقة، صلاحيات، رفع وسائط، نماذج إدخال، مسودات، نسخ سابقة، واجهة عربية RTL). هذا بالضبط ما تقدمه منصات CMS ناضجة جاهزاً ومختبراً، وبناؤه يدوياً: أسابيع عمل، وأمان أضعف، وصيانة على عاتق من لا يعرف إطاري الخاص.

## 4. تفاصيل القرار

**المنصة:** Next.js 16 (App Router) + Payload CMS 3.90 في تطبيق واحد؛ كل شيء TypeScript.

**قاعدة البيانات: SQLite (محول Payload الرسمي)** لأن:
- حجم المركز (آلاف العناصر) وحركة الكتابة الضئيلة لا تحتاج خادم قاعدة بيانات منفصلاً.
- أبسط تشغيلاً ونسخاً احتياطياً (ملف واحد)، وأتحقق منها هنا محلياً (Docker غير مشغّل في بيئة التطوير الحالية فلا يمكن اختبار Postgres).
- الانتقال إلى PostgreSQL لاحقاً تبديل محوّل (`@payloadcms/db-postgres`) دون تغيير نموذج المحتوى. **ما تأثر بالمحرك** (فهرس البحث FTS5) معزول في قاعدة بيانات مشتقة منفصلة قابلة لإعادة البناء.

**ما تم الاحتفاظ به من العمل السابق (مستقل عن الإطار):** مستورد الموقع القديم + لقطة المحتوى، المعقِّم، أدوات تطبيع العربية والتواريخ، كتالوج اللغات، مزوّدو الترجمة (Claude/Google/LibreTranslate/وهمي) ومقسّم HTML وقاموس المصطلحات، واختباراتها.

**ما استُبدل:** الخادم والقوالب المخصصة ← صفحات React Server Components؛ مخطط SQL المخصص ← مجموعات Payload؛ لوحة الإدارة المخصصة ← لوحة Payload؛ طابور الترجمة المخصص ← Payload Jobs Queue.

## 5. المخاطر وكيف نعالجها

| الخطر | المعالجة |
|---|---|
| حجم JS الأساسي لـNext (~100KB) أكبر من خادم HTML الصرف | صفحات Server Components بلا مكونات عميل إلا جزر صغيرة (بحث، لغة، سمة)، وتخزين ISR، وضغط Brotli، وPWA للقراءة دون اتصال. الموقع القديم نفسه Next.js فلا تراجع |
| 95 لغة كإعدادات `localization` | تُشتق من كتالوج واحد؛ الصفوف تُنشأ فقط عند وجود ترجمة؛ `filterAvailableLocales` يخفي غير المستخدم من واجهة الإدارة |
| إصدارات Next/Payload سريعة التغير | تثبيت الإصدارات الدقيقة وفق مصفوفة التوافق الرسمية (Payload 3.90.2 يدعم Next ≥ 16.3.3) + اختبارات تكامل |
| سجلات النسخ (versions) تتضخم مع الترجمات | الترجمات الآلية تُكتب على مستوى قاعدة البيانات دون إنشاء نسخ؛ نسخ المحررين محدودة العدد |
| محرر النص الغني | حقل HTML مخصص بمحرر TipTap ليبقى المحتوى HTML معقّماً (استيراد بلا فقد وترجمة أبسط) بدل JSON خاص بالمحرر |
